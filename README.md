# NearBuy — frontend preview

React SPA built with Vite and Tailwind CSS. No backend, database, server authentication or WebSocket service is included.

## Run locally

Install Node.js 20.19+ or 22.12+ and pnpm, then:

```sh
cd frontend
pnpm install
pnpm dev
```

Open the localhost URL printed by Vite (normally http://127.0.0.1:5173). `pnpm build` creates the production bundle; `pnpm preview` previews it.

## Preview workflows

- Explore `/`: search titles/descriptions/locations, filter categories and locations, sort by price, save favourites.
- `/login` and `/register`: buyer/seller selection and required fields, email, password length and confirmation validation. Demo login accepts any valid email and 8-character password. Passwords are not stored or verified. Registered names and email addresses are stored locally; use sample information.
- `/listing/1`: photo gallery, peer reviews, listing report, messaging. Switch the conversation speaker between Buyer and Seller to test both sides; no messages leave this browser.
- `/seller`: use the Seller preview button. Create/edit items, mark them sold, download Monthly Sales PDF and Daily Inquiries CSV. The initial seller is Nimal Perera. Newly registered sellers start with no listings.
- `/admin`: use Admin preview. Approve/remove flagged listings, suspend/reactivate users, inspect audit logs, download Daily Activity PDF and Audit CSV.
- All listings, conversations, reviews, account profiles, saves and logs persist in localStorage. Clear site data to reset the demo. Role gates are UI previews, not security controls.

PDF files are generated by jsPDF, and CSV fields are quoted and protected from leading formula characters. Reports reflect local state. Sales exports filter by the current calendar month; daily reports filter today's activity. Demo ratings and sample users are identified in the interface/report.

## Structure and scope

`frontend/src/main.jsx`: routes, shared local state, marketplace and dashboard components.
`frontend/src/data.js`: Sri Lankan mock marketplace listings and users.
`frontend/src/reports.js`: browser-only report downloads.
`frontend/src/styles.css`: Tailwind import and responsive application design.

Reference context: supplied NearBuy proposal presentation and university guideline screenshots. Backend requirements (REST API, PostgreSQL, password hashing, real authorization, durable audit logs, upload storage, verified reviews and real-time messaging) are intentionally deferred. No document instructions override this frontend-only scope.

Stock product images are illustrative and loaded from Unsplash; a local fallback is supplied if images cannot load. Google fonts are optional and have system fallbacks. The second gallery image is an illustrative colour variant, not an additional product photograph.

## Manual acceptance checks

1. Search `Sony`, filter Furniture, then choose a location with no matches; clear filters.
2. Save an item and view Saved; refresh to verify persistence.
3. Register with mismatched passwords, correct them, and submit.
4. Send Buyer and Seller messages on one listing; confirm another listing has its own chat.
5. Create and edit a listing, mark it sold, and confirm it disappears from the active marketplace.
6. Download each of the four reports; inspect PDF content and CSV headers.
7. Report a listing, remove it in Admin, and verify the audit event and marketplace update.
8. Check mobile width (390px), keyboard focus and empty states.
